# Commit 訊息（繁中）

撰寫或執行 git commit 時，訊息用這個格式。實際 commit 仍須使用者明確要求；安全流程（不改 git config、不 `--no-verify`、不 force push 等）照既有規則。

## 格式

```
<慣用字>: <精簡說明改了哪些功能>

- <細項>
- <細項>
```

- **首行**：一句話講「這次動到哪些功能／區塊」，不要列檔名、不要寫實作細節。
- **其後**：條列細項；每點一件具體變更。
- **語言**：說明與細項用繁體中文。慣用字保留英文（`update`、`feat`、`fix`、`add`、`docs`、`refactor`、`chore`）。
- **慣用字**：對應這次變更選一個。一般調整、文案／樣式微改用 `update`；新功能用 `feat`；修正用 `fix`。

## 慣用字對照

| 字 | 何時用 |
|---|---|
| `update` | 調整既有功能、文案、樣式、素材 |
| `feat` | 新增功能或區塊 |
| `fix` | 修正錯誤 |
| `add` | 新增檔案／素材，尚不構成獨立功能時 |
| `docs` | 只改說明文件 |
| `refactor` | 行為不變的整理 |
| `chore` | 雜務、設定、與功能無關 |

## 寫作規則

- 首行精簡，一個主題；多個不相關改動應拆 commit，不要硬塞一行。
- 細項寫「做了什麼」，不要寫「改了某某檔」。
- 不要英文長句當主體；專有名詞、檔名、QDM 後台路徑可夾在中文裡。
- 不要在訊息裡放 secrets。
- 沒有變更就不要空 commit。

## 範例

**例 1 — 調整既有頁面**

```
update: 調整首頁橫幅與商品說明

- 首頁橫幅改為新季主視覺
- 商品說明補上材質與尺寸
```

**例 2 — 新功能**

```
feat: 新增常見問題區塊

- 頁面加入 FAQ 摺疊列表
- 文案涵蓋出貨天數與客製注意事項
```

**例 3 — 修正**

```
fix: 修正行動版選單被頁首遮住

- 選單展開時提高層級
- 避免與購物車圖示重疊
```

**不要這樣寫**

```
update files
```

```
update: 改了 style.css 和 index.html
```
