# 瀏覽器協作流程

給 agent 用瀏覽器一起改 QDM 前後台時先看這份。這份是通用流程；**這間店的網址、帳號角色、看得到的選單寫在該分支的 `BRANCH.md`**。貼碼位置與選擇器以 `docs/qdm-layout-reference.md` 為準。

**不要**把後台 `token`、cookie、帳號或密碼寫進 repo、commit 或聊天紀錄。網址列上的 `token=` 是當次登入憑證，過期就失效，只存在瀏覽器分頁裡。帳密只放本機 `account/`。

---

## 前台

- 入口形如 `https://<商店>.qdm.tw/`
- 看版面、點選單、核對改完的畫面：直接開前台，不需登入
- 頁首「會員登入」是顧客帳，不是後台。改頁面時不要去登顧客帳

## 後台

- 入口形如 `https://<商店>.qdm.tw/admin/`
- 登入後看板路徑：`/admin/index.php?route=common/home`（後面的 `token` 由平台帶，不要抄下來）
- 登入成功的標題形如：`後台 - <商店名稱> :: 看板(Dashboard)`
- 共享者帳號只看得到被開通的主選單。沒開通的（常見是訂單、會員、商店設定、金物流）先不要點、不要猜路徑

右下角「QDM 開店顧問」是客服聊天，不要操作。頂部「登出」不要點。

---

## 用瀏覽器一起改時

1. 先確認目前分支，從 `BRANCH.md` 取得這間店的網域。
2. 列出現有分頁。網址已是該店網域或後台看板的，沿用，不要再開一個新登入。
3. 前台改完要在前台分頁核對；後台編輯留在後台分頁。兩邊都在時，不要互相覆蓋或關掉。
4. 後台若變成登入頁（要填帳號／密碼，或被導到登入），**停下來問使用者**。不要猜密碼，不要試登入。
5. 使用者說已登入後，再從現有後台分頁繼續；不要把新的 `token` 寫進檔案。
6. 只操作任務需要的畫面。未開通的模組先不動。
7. 分頁網域和目前分支的商店不符時，先停下來確認，避免把 A 店的片段貼到 B 店。
